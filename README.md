# Saee Life Herbal

A responsive core-PHP/MySQL agricultural product website, CMS and member portal. The public website and admin have separate installable PWA manifests. The code includes an order-request basket and a two-level referral wallet; it does **not** automatically collect payments or send bank transfers.

## Installation

1. Install PHP 8.1 or later with PDO MySQL, DOM, fileinfo and sessions, plus MySQL 5.7/8 or a compatible MariaDB. Create an empty UTF-8 MySQL database and import **both `schema.sql` and then `migration-002.sql`**, in that order. Existing databases created from the original starter should import only `migration-002.sql`, once. Back up before migrating. The migration is not idempotent.
2. Copy `api/config.example.php` to `api/config.php` and supply database credentials and the business timezone. This file is gitignored. Use a dedicated, least-privilege database account and restrict file permissions.
3. Create the first administrator once: `php api/create-admin.php 'Admin Name' admin@example.com 'a-strong-password'`. The administrator is also the default company sponsor, `COMPANY`. Use a unique strong password, and avoid leaving the command in shared shell history.
4. Make `uploads/` writable by PHP. Set `upload_max_filesize` to at least `30M` and `post_max_size` above that in PHP configuration for video uploads. On Apache, the included `uploads/.htaccess` blocks script execution. On Nginx or another server, explicitly disable script execution in `/uploads/` and deny public access to `.git`, SQL files, test files, backups and configuration. Serve over HTTPS and configure the web server to process `.php` files. For local development use `php -S 0.0.0.0:8000` from the project root.
5. Visit `/#admin` and sign in. Add real products, slides, pages, social links and business details before launch. Seeded products and product imagery are illustrative; seeded products are marked as samples and cannot be ordered until edited. Set a company sponsor ID that belongs to an existing member.

If PHP or the database is unavailable, the public shell falls back to sample content for a visual preview; login, checkout and admin are not operational in that mode. Installability requires HTTPS or localhost. Offline caching is limited to the public app shell, not live account or API data.

## How the workflows work

- **CMS:** Administrators can add, edit, publish and delete pages; edit homepage headings/copy and contact/brand settings; upload logo and favicon; and manage social links/icons. Hero slides support image upload, text visibility, duration and fade/zoom/no effect. Product descriptions and pages use a limited rich-text editor; markup is sanitized server-side. Products support multiple uploaded images and MP4/WebM videos. Uploaded files are limited to 30 MB each and checked by MIME type.
- **Orders:** Members can add products to a browser-local basket and submit an order request. No payment is taken at checkout. An administrator must confirm payment externally, then confirm the pending order with a unique receipt reference. Only then are commissions credited. An admin can also record a separately confirmed purchase with a unique receipt and quantity. Duplicate references are rejected across both workflows. Each line credits the buyer's direct sponsor and that sponsor's sponsor using the product's configured fixed amounts per unit. There is no automated refund or commission reversal.
- **Members:** Registration accepts an optional sponsor ID; an empty value uses the configured company sponsor. Members see their wallet ledger, direct referral count and orders, and can enter optional KYC and bank information. Updating those details invalidates existing verification. Administrators review and verify the submitted details manually; verification does not validate documents against a government service.
- **Rewards:** One-time milestone rules pay once when a direct-referral threshold is reached during registration. Monthly royalty rules use the member's current direct-referral count and are run manually for the current month; an eligible member is credited at most once per rule/month. This is not a historical snapshot or a scheduled job. Awarded rules cannot be edited or deleted.
- **Payouts:** Verified, complete KYC/bank information and sufficient wallet balance are required. A request reserves wallet funds; admins can approve, reject (refunds the reservation), or mark an approved payout paid after transferring funds outside the system. The bank details must still match the original request and the member must remain verified. The CSV report contains sensitive bank and KYC information; restrict and protect downloaded files.

## Verification

`tests/integration.py` is a destructive smoke test for a **fresh disposable database** and a running PHP server. Create the first admin as above, then run `BASE_URL=http://127.0.0.1:8000 ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='...' python3 tests/integration.py`. It covers authorization, uploads, sanitized content, sponsor credits, duplicate receipts, order confirmation, royalties, KYC and payouts. Do not run it against real customer data.

## Before production

This implementation is a foundation, not a certified payment, banking or MLM platform. It has no payment gateway, automated bank transfer, identity verification provider, scheduled royalty runner, returns/refunds, commission reversals, password reset, email verification, granular staff permissions or comprehensive audit trail. Some button labels and decorative template copy remain fixed in the template. Login throttling is basic, not a substitute for edge protection or MFA. KYC and bank data are stored in the database without field-level encryption. Before handling real customer data or money, implement encryption and key management, appropriate access controls, independent security testing, backups and retention policies, monitoring, reconciliation, fraud controls and an audited payment/payout integration. Get professional legal advice on Indian direct-selling/MLM, agricultural-product, privacy and consumer requirements, and disclose the actual plan terms to members.
